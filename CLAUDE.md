This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

One-page marketing site for "Escuela de Baile Lucy Arroyo" (a dance academy). Built on **TanStack Start** (React 19 + TanStack Router, SSR), Tailwind v4, shadcn/ui (`new-york` style), and Framer Motion. Package manager is **bun**. See `.lovable/plan.md` for the original design brief (visual identity, section-by-section content, animation approach) if you need context on intended look-and-feel.

This project is generated/synced via [Lovable](https://lovable.dev) — see the notice in `AGENTS.md`. Do not rewrite published git history (no force-push, no rebase/amend/squash of already-pushed commits) since that breaks Lovable's sync and can lose the user's project history in the editor. Keep the connected branch in a working (buildable) state, since every push syncs back to Lovable.

## Commands

Package manager is bun (`bun.lock` present) — use `bun`/`bunx`, not npm/yarn.

- `bun install` — install dependencies
- `bun run dev` — start dev server (`vite dev`)
- `bun run build` — production build (`vite build`)
- `bun run build:dev` — development-mode build
- `bun run preview` — preview a production build
- `bun run lint` — ESLint over the repo
- `bun run format` — Prettier write

There is no test suite configured in this repo.

## Architecture

### Routing
File-based routing via TanStack Router — every `.tsx` file under `src/routes/` becomes a route. Full conventions are documented in `src/routes/README.md` (dynamic `$id`, splat `$`, optional `{-$category}`, `_layout`, `__root`). Key points:
- Do **not** create `src/pages/` or Next.js/Remix-style route files — this is TanStack Start, not Next.js.
- `src/routeTree.gen.ts` is auto-generated by the router plugin — never edit by hand.
- `src/routes/__root.tsx` is the single app shell (`<html>`, `<head>`, fonts, SEO meta/OG tags, dark theme, `QueryClientProvider`, `Toaster`) and defines the 404/error boundary components.
- The site itself is a single page: `src/routes/index.tsx` just composes the section components in order (Navbar, Hero, Nosotros, Clases, Profesores, Galeria, Redes, Contacto, Footer) with in-page anchors — there's no multi-page nav.

### Component layout
- `src/components/site/` — one component per homepage section (Hero, Nosotros, Clases, Profesores, Galeria, Redes, Contacto, Navbar, Footer, Placeholder). This is where content/copy/layout changes for the page happen.
- `src/components/ui/` — shadcn/ui primitives (generated, not hand-rolled). Add new shadcn components with the standard shadcn CLI; config lives in `components.json` (aliases: `@/components`, `@/components/ui`, `@/lib`, `@/hooks`).
- `src/lib/motion.ts` — shared Framer Motion variants (`fadeUp`, `fadeIn`, `zoomIn`, `staggerParent`, `viewportOnce`). Reuse these instead of redefining animation variants per component.
- `src/styles.css` — Tailwind v4 + design tokens as OKLCH CSS variables (`--background`, `--primary`, `--accent`, etc.). Brand palette: near-black background, intense red primary. Fonts: Playfair Display (headings) and Manrope (body), loaded via `<link>` in `__root.tsx`.

### Assets
Media (video, images) uploaded through Lovable are tracked as `*.asset.json` files in `src/assets/` (metadata pointing at a Lovable/R2-hosted URL), not raw binaries committed to the repo. Import the `.asset.json` file and use its `.url` field rather than adding new binary assets directly, to stay consistent with the existing pattern (see `logo.png.asset.json` and its usage in `__root.tsx`).

### SSR error handling
There's a deliberate multi-layer error-handling setup worth understanding before touching server entry code:
- `src/start.ts` defines `errorMiddleware`, a server request middleware that catches unhandled errors and renders a fallback error page (`src/lib/error-page.ts`) instead of a raw 500.
- `src/server.ts` is the actual server entry (wired in via `vite.config.ts`'s `tanstackStart.server.entry: "server"`), wrapping the generated `@tanstack/react-start/server-entry` fetch handler. It additionally detects the case where h3 (the underlying server) swallows an in-handler throw into a generic `{"unhandled":true,"message":"HTTPError"}` JSON 500 — `try/catch` alone doesn't catch that — and recovers the real error via `src/lib/error-capture.ts`'s out-of-band `error`/`unhandledrejection` listeners so it can still be logged/rendered properly.
- `src/routes/__root.tsx`'s `ErrorComponent` reports client-side render errors to Lovable's error reporting via `src/lib/lovable-error-reporting.ts` (`window.__lovableEvents.captureException`).
- Don't remove or bypass this chain when editing server entry / root route error handling — it's what prevents raw framework error JSON from being shown to users.

### Build config
`vite.config.ts` uses `@lovable.dev/vite-tanstack-config`, which already bundles the TanStack Start, React, Tailwind, tsconfig-paths, and Nitro (Cloudflare target by default) plugins, plus dev-only tooling (component tagger, HMR gate, sandbox port/host detection). **Do not manually add these plugins again** — the config file has an explicit comment warning that duplicate plugins will break the app. Extend it via `defineConfig({ vite: {...}, tanstackStart: {...} })` only.

### Lint/format
ESLint flat config (`eslint.config.js`) extends typescript-eslint + react-hooks + react-refresh + Prettier. Notable custom rule: importing the Next.js `server-only` package is banned — TanStack Start's equivalent is naming the module `*.server.ts` or using `@tanstack/react-start/server-only`. `@typescript-eslint/no-unused-vars` is off; unused vars are not an error in this repo.

### Package installs
`bunfig.toml` enforces a 24-hour supply-chain guard (`minimumReleaseAge`) blocking freshly-published package versions. A small allowlist of Lovable-internal packages bypasses it. Confirm with the user before adding new entries to `minimumReleaseAgeExcludes`.
